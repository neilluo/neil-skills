API 网关提供多种认证鉴权机制，帮助保护后端服务的通信安全。本文对 API 网关支持的各认证方式进行概述，并从适用场景、安全级别、接入复杂度等维度进行对比分析，帮助您根据实际业务需求选择合适的认证方案。

<span id="4Je7jAcr"></span>
## 认证方式与访问控制总览

API 网关当前支持以下认证鉴权方式及访问控制机制：


* **HMAC 认证鉴权**：基于 HmacSHA256 算法，为 HTTP 请求生成不可伪造的 AK/SK 签名，防止请求被篡改或重放。

* **API Key 认证鉴权**：通过在请求头或请求参数中携带唯一标识的 Key 来验证调用方身份，接入方式简单直接。

* **JWT 认证鉴权**：基于 JSON Web Token 规范，在用户和服务器之间传递安全可靠的身份信息，适用于需要有状态身份标识的场景。

* **外部认证鉴权**：对接用户自建的认证鉴权服务，支持自定义 Token 格式，适用于已有独立认证体系的业务。

* **IP 黑白名单**：基于客户端 IP 地址进行访问控制，可配置允许或拒绝特定 IP 段的访问请求。

* **访问限流**：控制网关实例或路由级别的访问请求阈值，在指定统计周期内限制请求量，保障后端服务稳定性。

## 认证方式对比


|**认证方式** |凭证类型 |**适用场景** |**生效级别** |安全级别 |接入复杂度 |凭证有效期 |
|---|---|---|---|---|---|---|
|HMAC 认证 |AK/SK（访问密钥对） |服务间调用、开放平台 API、对安全性要求高的接口 |服务级别、路由级别 |高 |高 |长期有效 |
|API Key 认证 |API Key（唯一标识码） |内部系统集成、合作伙伴对接、快速接入场景 |服务级别、路由级别 |中 |低 |长期有效 |
|JWT 认证 |JSON Web Token |面向终端用户的 Web/App 应用、需要传递用户身份信息的场景 |服务级别 |高 |中 |7 天有效 |
|外部认证 |自定义 Token |已有自建认证体系、需统一认证方式、自定义 Token 格式的业务 |实例级别 |高 |高 |自建认证服务定义 |
