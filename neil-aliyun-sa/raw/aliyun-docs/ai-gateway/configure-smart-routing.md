本文介绍如何为 OpenAI 兼容或 Anthropic 兼容的文本生成 Model API 配置智能路由，并通过 `auto/<目标>` 调用候选模型池。  

## 功能与适用范围
智能路由是一种文本生成 Model API 服务类型。您在网关中维护一个候选模型池，应用只需在请求的 `model` 字段声明本次调用的优化目标，AI 网关会结合请求特征、目标和候选模型的可用能力，选择合适的候选模型执行请求。

当前智能路由支持**OpenAI 兼容** 和**Anthropic 兼容**的文本生成 Model API。应用仍使用原有协议和对应路径调用，例如 OpenAI 兼容的 Chat Completions 或 Responses 路径，以及 Anthropic 兼容的 Messages 路径；无需为智能路由接入新的应用协议。

智能路由适合简单问答、内容生成、代码辅助和 Agent 等请求类型混合的业务。您可以在不修改应用中具体模型名称的前提下，集中调整候选模型池，并按成本、质量或响应速度选择不同的优化目标。  
**重要**

智能路由的请求模型名必须显式使用 `auto/<目标>`，例如 `auto/balanced`。单独填写 `auto` 不会作为默认目标使用。

## 智能路由的工作方式
1. 在 Model API 中配置候选来源：可以使用系统内置模型、您自定义的模型服务（包括 BYOK 模型），也可以同时使用两种来源。

2. 调用方在请求的 `model` 字段中填写 `auto/<目标>`，表达本次调用更重视成本、质量、速度还是综合均衡。

3. 网关只会在满足当前协议、请求路径、输入输出类型、Token 上限和能力要求的候选模型中进行选择。

4. 选中的模型通过其关联的 AI 服务执行请求，响应仍按照您选择的 OpenAI 兼容或 Anthropic 兼容协议返回。

优化目标表达的是业务偏好，而不是固定模型名称或强制规则。例如，`auto/cheap` 会在可用候选中优先考虑成本更低的模型，但不会绕过协议、能力或输入限制；它也不承诺每次都调用同一具体模型或绝对价格最低的模型。

## 前提条件
* 已创建 AI 网关实例，并具备该实例的 Model API、AI 服务和模型元信息配置权限。

* 智能路由需要单独开通。在创建 Model API 时选择**智能路由** 后，如果页面显示**请开通智能路由** ，请单击**前往开通**并按页面指引完成开通。功能未开通时，无法完成智能路由配置。

* 已为自定义模型创建可用的 AI 服务，并完成服务的访问凭据、网络和连通性配置。

* 已维护模型元信息，并确保模型元信息中的协议路径和能力与上游模型实际能力一致。

* 智能路由 Model API 默认启用消费者鉴权，且在服务类型为智能路由时不能关闭。已为调用方创建消费者、配置认证凭据，并向该消费者授予目标 Model API 的调用权限。

## 准备候选模型
候选模型由"模型元信息 + 模型供应商 + 已关联的 AI 服务"共同确定。智能路由不会把名称相同但未关联服务、协议不匹配或元信息缺失的模型作为可用候选。

### 配置供应商与 AI 服务关联

1. 在**AI 服务**中创建或确认自定义模型的服务。对于 BYOK 模型，请在该 AI 服务中配置您自己的访问凭据和服务地址。

2. 在**模型元信息** 的**供应商** 页签中，找到该模型所属供应商，并使用**管理关联服务**将对应 AI 服务关联到该供应商。

3. 确认服务、供应商和模型元信息处于同一实例，且服务能够按模型元信息声明的协议路径正常调用。

配置候选时，每一个自定义候选都是一个"已关联的 AI 服务 + 具体模型"的组合。同一 AI 服务可以配置多个不同模型，但重复的服务与模型组合不能重复添加。

## 创建智能路由 Model API
1. 登录[AI 网关控制台](https://apigw.console.aliyun.com/#/cn-hangzhou/ai-gateway)，进入目标 AI 网关实例。

2. 在左侧导航栏选择**Model API** ，然后单击**创建 Model API**。

3. 在**文本生成** 场景中，选择应用所使用的**OpenAI 兼容** 或**Anthropic 兼容**协议。控制台会按协议生成相应的默认路由；请保留业务需要的路径。

4. 填写 API 名称、域名和 Base Path。API 名称仅用于管理和标识接口，不决定请求中的智能路由模型名。

5. 在**大模型服务** 区域的**服务类型** 中选择**智能路由** 。如果出现**请开通智能路由** 提示，请单击**前往开通**，完成开通后返回此页面继续配置。

6. 按业务需要启用系统内置模型、添加自定义候选模型，或同时配置两者。添加自定义候选时，选择已关联供应商的 AI 服务及其具体模型。

7. 确认默认开启的消费者鉴权配置，为调用方创建消费者、配置凭据并完成授权后，再完成域名和其他 API 配置，单击**确定**保存。若控制台提示发布或生效操作，请按提示完成发布。

## 调用智能路由
智能路由不使用 API 名称作为请求模型名。调用方必须在请求体的 `model` 字段中显式传入 `auto/<目标>`。例如，即使您的 Model API 名称为 `my-router`，请求模型名仍应为 `auto/balanced`。

以上四个目标的设计重点是让调用方只声明业务意图，而不必了解候选池中每个模型的厂商、价格和能力差异。网关会先排除不适配当前请求的候选，再在其余候选中按目标进行选择。因此，优化目标不是固定模型别名，也不能保证每次返回同一具体模型。

### OpenAI 兼容调用示例

下面示例以 Chat Completions 路径和 API Key 消费者认证为例。智能路由 Model API 默认启用消费者鉴权；请先完成消费者授权，再按实际配置的认证方式携带凭据。

```
HELPCODEESCAPE-shell
curl https://<your-domain>/<base-path>/v1/chat/completions \
  -H "Authorization: Bearer <API-KEY>" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "auto/balanced",
    "messages": [
      {"role": "user", "content": "请帮我总结这段内容。"}
    ]
  }'
```

如果您为 OpenAI 兼容 Model API 配置了 Responses 路径，也可以继续使用对应的 Responses 请求格式，并将 `model` 改为 `auto/<目标>`。

### Anthropic 兼容调用示例

Anthropic 兼容 Model API 使用原生的 Messages 请求格式。除协议所需的请求头外，调用方还必须按智能路由 Model API 的消费者鉴权配置携带网关认证凭据；凭据字段以实际选择的认证方式为准。

```
HELPCODEESCAPE-json
POST /v1/messages

{
  "model": "auto/quality",
  "max_tokens": 1024,
  "messages": [
    {
      "role": "user",
      "content": "请为以下需求生成实现方案。"
    }
  ]
}
```

**重要**

在服务类型为**智能路由** 的 Model API 中，`model` 字段不能用于指定候选池中的具体模型名称。填写 `qwen3.7-flash`、`claude-*` 等具体模型名不会触发智能路由。若业务必须固定使用某一模型，请新建或调用非智能路由的 Model API，例如单服务或按模型名称路由的 Model API。

## 验证与日常维护
1. 在**Model API** 列表中找到目标 API，使用控制台调试功能，分别以 `auto/balanced` 和业务需要的其他目标发送测试请求。

2. 验证 OpenAI 兼容或 Anthropic 兼容的实际调用路径、消费者认证凭据和请求格式与应用保持一致。

3. 新增模型、调整候选模型、修改 AI 服务或服务关联后，按控制台提示保存并发布配置，再通过业务请求验证。

4. 当上游模型升级、下线、变更协议能力、调整上下文长度或修改价格时，同步更新模型元信息和候选配置。

**说明**

智能路由会对请求进行语义分析，可能产生额外 Token 消耗。请在成本评估中一并考虑，具体计费以[AI Credits 计费说明](https://help.aliyun.com/document_detail/3048572.html)为准。

## 常见问题
### 智能路由会改变应用调用协议吗？

不会。OpenAI 兼容 Model API 仍使用已配置的 OpenAI 兼容路径和请求格式；Anthropic 兼容 Model API 仍使用 `/v1/messages` 及 Anthropic 请求格式。调用方需要做的核心改动是将请求中的 `model` 显式改为 `auto/<目标>`。

### 为什么我填写了具体模型名，却没有使用智能路由？

具体模型名表示直接按该模型名调用，不是智能路由的入口。智能路由只识别 `auto/balanced`、`auto/cheap`、`auto/quality` 或 `auto/fast` 这类请求模型名。

### 为什么同一优化目标的实际处理模型可能不同？

智能路由的目标是从当前可用、且满足本次请求要求的候选中选择合适的模型，而不是将一个目标固定绑定到一个模型。候选池、模型元信息、请求内容和能力要求发生变化时，实际处理模型也可能不同。若必须固定模型，请使用非智能路由的 Model API。

### 请求没有可用候选模型时，应该检查什么？

依次检查请求中的 `model` 是否为 `auto/<目标>`、候选模型是否支持当前协议和路径、模型元信息中的 Token 与能力信息是否准确，以及自定义模型的 AI 服务是否已关联到正确的模型供应商并可正常访问。
