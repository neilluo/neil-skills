## 重点画像（深度蒸馏）

### 南京银行

**一句话定位**：城商行金融分布式架构标杆，SOFAStack + OceanBase 路线全行级落地。
**业务规模**：城商行 TOP 梯队；线上消费金融"鑫云+"产品。
**业务模式**：传统对公对私 + 互联网消费金融。
**主战场地域**：江苏 + 全国互联网消费金融。

**当前云使用情况**：
- 主要云厂：阿里云（蚂蚁 SOFAStack 体系）
- 关键产品：SOFAStack（微服务/分布式事务/服务治理） + OceanBase（金融级分布式数据库）
- 上线时间：2017 年 11 月

**架构亮点**：
- 单体架构 → 金融级分布式（双中台模式）
- 单库单表瓶颈 → OceanBase 分布式
- 高并发场景：日单 100 万笔，放款 1 秒级

**量化收益**：
- 放款时效：从分钟级到秒级（~1 秒/笔）
- 日处理订单：100 万笔
- 开发效率提升：行业平均 +80%
- 运维成本下降：行业平均 -90%

**典型话术**：
> "城商行做互联网消费金融，传统集中式架构撑不住高并发；SOFAStack + OceanBase 是经过蚂蚁双 11 验证的金融级分布式标准答案。"

**信息来源**：https://help.aliyun.com/zh/document_detail/194962.html、https://help.aliyun.com/zh/document_detail/313938.html
**最近更新**：2026-06-17
**敏感等级**：公开（官方案例）

### 哈啰出行

**一句话定位**：本地出行/共享单车头部，AI Agent 全场景落地代表客户。
**业务规模**：日活千万级、城市覆盖全国 400+ 城市。
**业务模式**：共享单车 + 网约车 + 哈啰电动车 + 本地生活。
**主战场地域**：国内全城市。

**当前云使用情况**：
- 主要云厂：阿里云
- 关键产品：**SLS（日志服务）** —— TB 级日志统一接入；**百炼 + Agent**（客服 Copilot 升级 Agent + 营销内容生成）
- 原架构：Kafka + ELK + ClickHouse（多套）
- 现架构：统一迁移至 SLS

**架构亮点**：
- 日志统一：从 ELK + ClickHouse 多套合并为 SLS 单平台
- AI 应用：Copilot → Agent 演进，从辅助到主动决策
- 多业务线复用同一 AI 底座（客服、营销）

**量化收益**：
- 日志成本：-30%（SLS vs 自建 ELK + ClickHouse）
- 查询：从不可用到秒级
- AI Agent：约课率 + 出席率双提升（教育业务，引用 51Talk 同模式）

**信息来源**：https://help.aliyun.com/zh/sls/hellobike、developer.aliyun.com/article/1647416
**最近更新**：2026-06-17
**敏感等级**：公开（官方案例）

## 心动网络

**一句话定位**：中国互联网百强游戏公司，PolarDB 全业务构建标杆，支撑百万级玩家并发与全球化发行。

**主战场地域**：中国 + 东南亚 + 欧美。

**当前云使用情况**：
- 主要云厂：阿里云
- 关键产品：**PolarDB MySQL**（全部业务系统）
- 部署：全球多 Region（东南亚低延迟要求）

**架构亮点**：
- 存储计算分离：一主 + 多只读节点，3 倍 MySQL 性能
- 100 万级玩家同时在线，活动峰值高并发
- 秒级故障恢复（30s~60s 主备切换）
- 服务端重启场景：PolarDB 高性能读能力支撑快速恢复
- 100% 兼容 MySQL 5.6/5.7/8.0，生态无缝迁移

**量化收益**：
- 并发：支撑 100 万+ 玩家同时在线
- 恢复：故障切换 30~60 秒
- 备份：免费数据备份容灾，三副本一致性
- 兼容：100% MySQL 兼容，中间件零改造

**可迁移性**：适用于所有全球化游戏发行 + 高并发 + 快速弹性场景。TapTap 社区类业务同样适配。

### 雅迪科技（PolarDB for AI）

**一句话定位**：全球电动车销量第一，PolarDB for AI + DMS 实现 NL2SQL 数据查询 + RAG 智能问答，赋能 10 万+ 销售人员。

**业务模式**：电动车研发/制造/销售 + 云销通 App（服务商一站式管理）。
**主战场地域**：国内 + 越南/印尼等海外基地。

**当前云使用情况**：
- 主要云厂：阿里云
- 关键产品：**PolarDB for AI**（NL2SQL + RAG）+ **DMS**（数据管理服务）
- 应用载体：雅迪云销通 App（面向 2000+ 经销商、4 万+ 门店）

**架构亮点**：
- **NL2SQL**：销售人员自然语言提问 → SQL 查询 → 多模态结果展示（图表/表格/文字），覆盖 50+ 数据域（批发/销售/库存/采购/供应链/营销）
- **RAG 自由问答**：基于 PolarDB for AI 的检索增强生成，一键生成标准化策划文案（门店开业/活动营销/销售技巧）
- **Data+AI 融合**：数据库内置 AI，避免数据出库，一站式服务
- 查询准确率 > 90%

**量化收益**：
- 覆盖人群：10 万+ 销售人员实时数据查询
- 数据域：50+ 业务维度
- 准确率：> 90%（NL2SQL）
- 效率：从 "等报表" → "开口问"，决策响应从天级到秒级

**典型话术**：
> "制造业 10 万+ 一线销售人员不懂 SQL，PolarDB for AI 的 NL2SQL + RAG 让他们'用嘴查数据'，查询准确率 > 90%。这是 Data+AI 融合的标杆级落地。"

**可迁移性**：所有拥有大量一线业务人员 + 多数据域查询需求的制造/零售企业均可复制。关键约束：①需要高质量的 Schema 标注和数据治理；②RAG 知识库需业务团队持续维护。

## 蒸馏方法论：客户档案怎么写

每张档案卡至少要回答 5 个问题：

1. **是谁**（业务、规模、地域）
2. **遇到了什么问题**（原架构痛点）
3. **用了阿里云什么**（精确产品名 + 架构组合）
4. **效果是什么**（量化数字 — 没有数字的"提升明显"是营销话术，要打折）
5. **可迁移性**（这套做法别的客户能不能复刻、约束条件是什么）

每个客户至少要有 3 张可对外讲的"故事卡"：
- 1 张面向 CTO（技术决策） — 架构图 + 选型理由
- 1 张面向 CFO（成本决策） — TCO 对比 + ROI
- 1 张面向 CEO（战略决策） — 业务价值 + 行业地位
