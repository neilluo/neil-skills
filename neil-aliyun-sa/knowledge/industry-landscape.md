## 制造业（离散制造 + 流程制造）[官方+推断]

**市场规模与增长**：
- 中国工业互联网市场规模：~1.2 万亿元（2024），+12% YoY
- 制造业上云渗透率：~35%（主要集中在 SaaS/ERP，IaaS+PaaS 仍有增长空间）
- 智能制造投入占 IT 预算：15-25%（头部企业更高）

**典型业务模式**：
- 离散制造（汽车/电子/机械）：多品种小批量 → 柔性产线 + MES + 质检
- 流程制造（化工/钢铁/食品）：连续生产 → 设备监控 + 能耗优化 + 预测性维护
- 共性：ERP(SAP/用友/金蝶) + MES + PLM + WMS + SRM 复杂系统群

**核心痛点**：
- 系统孤岛：ERP/MES/PLM/WMS 数据不通，决策依赖人工汇总
- 质量管理：人工质检效率低、漏检率高、追溯困难
- 供应链不确定：原材料价格波动、供应商交付不稳定、库存成本高
- IT 人才匮乏：传统制造企业 IT 团队 5-20 人，无力维护复杂系统
- 数据安全：工艺参数/BOM 是核心竞争力，对数据出域极其敏感

**技术栈共性**：
- 核心系统：SAP ECC/S4HANA（大型）或用友U8+/金蝶K3+（中型）
- 产线系统：MES + SCADA + PLC + 工业以太网
- 数据库：Oracle/SQL Server 为主（历史包袱重）
- 网络：工厂内网 + VPN/专线连总部
- 典型 IT 架构年龄：5-15 年，自建 IDC

**云需求特征**（六维）：
| 维度 | 需求 | 产品映射 |
| --- | --- | --- |
| 计算 | 混合云（工厂边缘+公有云） | ECS + ENS + ACK Edge |
| 存储 | 大量图片/视频（质检）+ 文档 | OSS + NAS |
| 网络 | 工厂→云专线/VPN | CEN + VPN Gateway + SAG |
| 数据 | IoT 时序数据 + BI 分析 | IoT平台 + Lindorm + DataWorks |
| AI | 视觉质检 + 知识问答 + 预测 | PAI + 百炼 + Qwen-VL |
| 安全 | 等保 + 工艺数据保护 | 云安全中心 + 数据库审计 |

**合规要点**：
- 等保二级/三级（视业务关键性）
- 工业数据分类分级（工信部要求）
- 工艺参数/核心技术数据不可出境（视企业要求）
- ISO 9001 / IATF 16949（汽车零部件）/ GMP（制药）行业标准

**竞争格局**：
| 厂商 | 定位 | 优势 | 代表客户 |
| --- | --- | --- | --- |
| 阿里云 | 工业互联网平台 + AI | 数据中台+AI+IoT平台 | 攀钢、中策橡胶、正泰电器 |
| 华为云 | 工业智能体 + 边缘 | 硬件全栈（5G+边缘+云）、政企关系 | 一汽、宝钢、三一重工 |
| 腾讯云 | WeMake + 微信生态 | 社交协同+轻量化 | 富士康、格力 |
| 树根互联 | 工业互联网独立平台 | 深耕制造、三一背景 | 三一重工、中联重科 |
| 用友/金蝶 | ERP+工业互联网 | 企业管理软件基础 | 传统制造业广泛 |

**阿里云差异化优势**：
- 阿里云 IoT 平台 + 数字孪生
- PAI 工业质检方案（iTAG标注 + DSW训练 + EAS部署，端到端闭环）
- 百炼 AI Agent 平台（企业知识库 + 多Agent）
- 数据中台（DataWorks + MaxCompute）处理 IoT 数据
- 边缘计算（ENS + ACK@Edge）满足产线实时性

**典型客户案例**：

**踩坑/敏感点**：
- 客户数据安全顾虑极强（必须强调 VPC 隔离+加密+审计）
- 工厂网络环境差（需考虑离线/弱网模式）
- ERP 集成复杂（SAP RFC/BAPI 对接需专业团队）
- 长销售周期（6-18 个月），需与 SI 合作
- 预算审批流程长（需证明 ROI，量化节省工时/良率提升）

## 金融行业（银行 + 保险 + 证券）[官方+实战]

**市场规模与增长**：
- 2024 金融云市场：692 亿元，+11% YoY（IDC）
- 2025 H1：3801 亿元(含广义)，+20% YoY
- 金融公有云基础设施：阿里云 41% 市占率

**典型业务模式**：
- 银行：存贷汇核心、支付清算、信贷风控、财富管理、监管报送
- 保险：核心保单、精算、理赔、代理人管理
- 证券：交易撮合、行情推送、量化策略、投顾AI

**核心痛点**：
1. 业务连续性要求极致（宕机 1 分钟 = 数百万资损 + 监管问责）
2. 核心系统 Oracle/IBM 依赖深，迁移风险高
3. 信创时间表压力（国产化替代年度目标考核）
4. 互联网金融冲击传统架构（日百万笔消费贷 vs 单体核心）
5. 数据安全监管日趋严格

**技术栈共性**：
- 大行：Oracle + IBM WAS + F5 + EMC 存储 → 正在迁往 OceanBase/GaussDB + 国产中间件
- 城商行：MySQL 或 Oracle → SOFAStack + OceanBase/PolarDB-X
- 互联网银行/保险：云原生起步，分布式架构原生
- 共性：数据库是核心资产；中间件是"胶水"；安全是底线

**云需求特征**（六维）：
- 计算：金融专区物理隔离、等保四级
- 存储：加密存储(TDE+KMS)、数据不出境
- 网络：专线接入(高速通道)、网络隔离(Cloud Firewall)
- 数据：两地三中心容灾、RPO=0/RTO<分钟
- AI：智能风控、智能客服、AI 运维诊断
- 安全：等保四级、操作审计(ActionTrail)、密钥合规(FIPS 140-2 Level3)

**合规要点**：
| 法规 | 关键要求 |
| --- | --- |
| 银保监会容灾6级 | RTO≤1min, RPO=0, 两地三中心, 年度演练 |
| 等保四级 | 网络/主机/应用/数据四层安全控制，物理隔离 |
| 个人信息保护法(PIPL) | 金融数据最小化、加密、用户权利保障 |
| 数据安全法 | 数据分类分级、重要数据目录、跨境传输限制 |
| 反洗钱(AML/KYC) | 实时交易监控、身份验证、可疑交易报告 |
| 银行保险机构数据安全管理办法(2024) | 数据分级分类、访问控制、云安全管理 |

**竞争格局（云厂商分布）**：

| 维度 | 阿里云/蚂蚁 | 华为云 | 腾讯云 |
| --- | --- | --- | --- |
| 金融云整体 | #1 (18.4%) | 强私有云 | #2 平台解决方案(~15%) |
| 平台解决方案 | #1 (32%，首破30%) | 在列 | #2 |
| 公有云基础设施 | #1 (41%) | 弱 | 在列 |
| 私有云基础设施 | 在列 | **#1（连续7年）** | 增长最快(+45.7% YoY) |
| 核心数据库 | OceanBase(21.2%分布式DB) | GaussDB | TDSQL |
| 信创定位 | OceanBase + 飞天 | 鲲鹏全栈(芯→云) | TDSQL + 国产化 |
| 关键差异 | 互联网金融验证(双11) | 硬件垂直整合(芯片→云) | 微众银行参考架构 |
| 短板 | 私有云弱 | 公有云规模小 | 大行客户少 |

**典型客户**：
| 客户 | 类型 | 产品组合 | 量化收益 | 证据等级 |
| --- | --- | --- | --- | --- |
| 南京银行 | 城商行 | SOFAStack + OceanBase | 放款1秒/笔，日100万笔，运维-90% | [官方] |
| 网商银行 | 互联网银行 | 决策树+FaaS+Agent | 故障恢复3分钟，准确率93.5% | [实战-ATA] |
| 工商银行 | 大行 | OceanBase部署 | — | [官方-IDC] |
| 恒生银行 | 外资 | 阿里云国际 | — | [官方] |
| GCash | 支付 | IaaS+MaxCompute | 东南亚最大移动支付 | [官方] |

**阿里云差异化优势**：
1. OceanBase：分布式DB市占率21.2% #1，2000+客户，5/6大行覆盖，TPC-C世界纪录707M tpmC
2. SOFAStack：蚂蚁双11亿级交易验证，金融级分布式事务+多活
3. PolarDB-X两地三中心：5副本Paxos原生满足银保监会6级
4. 金融云等保四级认证：独立物理集群，SLA 99.98%(计算)/99.97%(DB)
5. 城商行标杆可复制：南京银行全行级生产验证（非PoC）

**踩坑/敏感点**：
- OceanBase vs PolarDB-X 内部选型容易混淆——OceanBase偏Oracle替代+强一致；PolarDB-X偏MySQL弹性+云原生
- 大行私有云部署需求高——阿里云在私有云(Stack)不如华为云
- 信创是政治正确——不能只讲技术优势，要讲合规资质
- 金融客户决策链长（6-12个月）——需要POC+试点+全行推广三阶段

## 零售/消费品行业（全渠道零售 + 新零售 + 供应链数字化）[官方+推断]

**市场规模与增长**：
- 中国零售数字化投入规模：~5 万亿元（2025E），其中 IT 基础设施+SaaS 占比约 8-12% [推断]
- 社会消费品零售总额：47.1 万亿元（2024），+3.5% YoY [官方]
- 全渠道零售 SaaS 市场：~600 亿元（2025E），+18% YoY [推断]
- 线上渗透率已达 30%+，增量在全渠道融合而非纯线上

**典型业务模式**：
- 全渠道零售：线上（天猫/京东/抖音/私域小程序）+ 线下（门店POS/自助终端）统一库存、统一会员
- 新零售/即时零售：前置仓+门店仓+中心仓 三级库存网络，30 分钟达
- 品牌 DTC：绕开经销商，直连消费者，私域运营（企微+小程序+CDP）
- 供应链数字化：需求预测 → 智能补货 → 仓配调度 → 末端配送
- 智能门店：AI 客流分析、电子价签、无人结算、AR 试穿/试妆

**核心痛点**：
- 线上线下系统割裂：库存不统一导致超卖/缺货，各渠道会员体系独立
- 会员数据孤岛：天猫/微信/线下 POS 三套用户画像无法打通，复购率低
- 供应链预测难：新品冷启动无历史数据、促销脉冲式流量难以准确预测
- 大促弹性不足：双11/618 流量 10-50x 平时，自建 IDC 资源浪费严重
- 门店数字化落地难：全国数千门店网络质量参差，IT 运维人力不足
- 数据驱动决策弱：BI 报表延迟 T+1，无法支撑实时经营调整
- 私域流量转化低：缺乏个性化推荐能力，用户触达同质化严重

**技术栈共性**：
- 电商中台：自研/商派/有赞/微盟（中小品牌）
- ERP：SAP（大型连锁）/ 用友U8+/管家婆（中小）
- 数据库：MySQL + Redis（线上）; Oracle/SQL Server（线下 ERP）
- 消息队列：Kafka/RocketMQ（订单流转）
- 前端：小程序 + H5 + App（React Native/Flutter）
- CDN：图片/视频加速为核心场景
- 典型 IT 团队规模：大型零售 50-200 人，中小品牌 10-30 人

**云需求特征**（六维）：
| 维度 | 需求 | 产品映射 |
| --- | --- | --- |
| 计算 | 大促弹性（10x 扩缩）+ 门店边缘计算 | ECS Auto Scaling + SAE + ENS |
| 存储 | 商品图片/视频（PB级）+ 日志归档 | OSS + IA/Archive 存储 |
| 网络 | 全国门店组网 + CDN 加速 | SAG 门店组网 + CDN/DCDN + GA 全球加速 |
| 数据 | 全渠道数据中台 + 实时 BI | DataWorks + MaxCompute + Quick BI + Flink |
| AI | 个性化推荐 + 智能客服 + 需求预测 | 百炼推荐 Agent + PAI-EAS + 通义千问 |
| 安全 | 用户隐私保护 + 支付安全 | WAF + 数据安全中心 + PCI-DSS 合规 |

**合规要点**：
- 等保二级（基本）/ 三级（涉及支付、金融牌照场景）
- 《个人信息保护法》(PIPL)：会员数据收集需明示同意、最小化原则
- 《消费者权益保护法》：用户画像需提供关闭选项
- PCI-DSS：涉及银行卡支付需合规（通常交由支付宝/微信支付承担）
- 跨境电商：GDPR（欧洲）/CCPA（美国）数据出境需评估
- 食品行业额外：食品安全追溯体系要求

**典型业务模式**：
- 车联网 T-Box：车载终端实时上报车况/位置/驾驶行为 → 云端汇聚分析 → OTA 下发

- 低延迟控制指令：OTA 升级/远程控车指令需端到端 <500ms，可靠性 99.99%+
- 训练算力需求爆发：自动驾驶模型训练需千卡 GPU 集群，排队等资源
- 数据标注成本高：自动驾驶 3D 点云标注人工成本高、周期长
- 多云/混合云复杂：研发云(AWS/Azure) + 国内量产云 + 边缘云 多环境协同

**技术栈共性**：
- 车端：QNX/Linux + ROS2 + 自研中间件
- 云端数据管道：Kafka/Pulsar(消息) + Spark/Flink(计算) + HDFS/对象存储
- 数据库：时序数据库(InfluxDB/TDengine/Lindorm) + MySQL/PostgreSQL(业务)
- AI 训练：PyTorch + NVIDIA GPU(A100/H100) + 分布式训练(DeepSpeed/Megatron)
- 仿真：CARLA/LGSVL + 自研仿真平台 + 大规模并行仿真(ECS 集群)
- 地图：高精地图自研(百度/高德/Momenta) + 点云处理(PCL/Open3D)
