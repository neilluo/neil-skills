## 0. 为什么必须做这个实验

**门禁全绿 / 满分本身是失效信号。** 首轮正控跑出 `PASS: 77/77`、整体命中率 `100.0%`、新增 AG01~AG15 **全部 100%** ——
这种结果的第一解释不是「知识库很完整」，而是「**用例可能根本没在测被测对象**」。

keyword 命中率只能证明「该写的写了」，**证明不了两件事**：
1. 命中是来自**新写的专题页**，还是来自别处（例如 `aliyun-products.md` 里那张密集的指针卡）；
2. 「**不该写的没写**」—— 错误断言一旦混进知识库，keyword 用例永远抓不到。

因此本次做两个负控 + 一次能力补强。

## 1. 🔴 负控 1：剔除被测对象（发现并修掉一个真缺陷）

**方法**：从 `tests/regression-cases.yaml` 的 `files.knowledge` 里删掉 7 个 AI 网关专题页，
使语料只剩 `aliyun-products.md` / `aliyun-agentcore.md` / 其余 knowledge + references，然后复跑。

**首轮结果（AG 组强化前）**：

```
PASS: 65/77  FAIL: 12/77
  ✅ AG01 — 8/8  (100%)     ← 🔴 剔除专题页后仍满分
  ✅ AG02 — 9/9  (100%)     ← 🔴 同上
  ✅ AG03 — 8/8  (100%)     ← 🔴 同上
  ❌ AG04 — 2/7  (29%)
  ❌ AG05 — 3/6  (50%)
  ... AG06~AG15 全部 FAIL
```

**🔴 这就是负控要抓的缺陷**：AG01/AG02/AG03 **证明不了专题页存在**。
根因 = 我（主控）写的 `aliyun-products.md` 指针卡太密集，把归属辨析、四形态起步价、三本账、
六类连带、私网 0.049 > 公网 0.037 等结论**全写进了一张卡**，于是这三个用例的关键词在指针卡里就能全命中。
若哪天 7 个专题页被误删或改坏，这三个用例**依然全绿**。

**修复**：给 AG01/AG02/AG03 各加 3~4 条**锚定关键词**，选取标准是实测
「在专题页家族命中 > 0 **且** 在 `aliyun-products.md` 命中 **= 0**」：

| 用例 | 新增锚定关键词 | 专题页命中 | `aliyun-products.md` 命中 |
|---|---|---|---|
| AG01 | `what-is-an-ai-gateway` / `Higress 开源版` / `product-comparison` | 36 / 11 / 17 | **0 / 0 / 0** |
| AG02 | `capacity-description` / `在线路由总数` / `1,280,000` | 84 / 8 / 1 | **0 / 0 / 0** |
| AG03 | `账单地板` / `超额累进` / `消费者规则扩容数` / `延停权益` | 2 / 4 / 3 / 8 | **0 / 0 / 0 / 0** |

**修复后复跑负控 1**：

```
PASS: 62/77  FAIL: 15/77
  ❌ AG01 — 8/11 (73%)     ✅ 现在会 FAIL
  ❌ AG02 — 9/12 (75%)     ✅ 现在会 FAIL
  ❌ AG03 — 8/12 (67%)     ✅ 现在会 FAIL
  ❌ AG04~AG15 全部 FAIL
```

→ **15/15 全部 FAIL**，证明 AG 组每一条都真的在测那 7 个专题页。**负控 1 通过。**

## 2. 🔴 负控 2：注入必然命中的 forbidden（证明新加的否证逻辑真的会 FAIL）

**背景**：本次给 `run-regression.py` 新增了 `forbidden` 不变量能力（原测试器只有关键词命中率）。
**新加的门禁能力必须自证会 FAIL**，否则等于没加 —— 一个恒不触发的 forbidden 检查和一个不存在的检查没有区别。

**方法**：把 AG04 的 `forbidden` 临时加上一条**语料里确实存在**的串 `无赔偿区`（它本就是 AG04 的 keyword 之一），
预期：AG04 关键词 **7/7 = 100% 命中**，但**因 forbidden 命中而 FAIL**。

**结果**：

```
PASS: 76/77  FAIL: 1/77
forbidden 不变量: 9 条，违反 1 条
  ❌ AG04 — 7/7 (100%)  🔴 违反禁写串: 无赔偿区
```

→ 证明三点：① `forbidden` 解析生效；② **违反即 FAIL 且能推翻 100% 命中率**（否证优先于印证）；
③ 报告与控制台都能指出**具体违反了哪条禁写串**（可定位，不是只给个红叉）。**负控 2 通过。**

## 4. AG 组的 8 条 forbidden 不变量（本次新增的否证面）

| 用例 | 禁写串 | 为什么这是会导致对客事故的错误断言 |
|---|---|---|
| AG01 | `AI 网关是独立 productCode 文档根` | 归属搞错会让 250 页 OpenAPI 参考淹没核心内容（AgentCore 侧已有同源教训） |
| AG03 | `私网比公网便宜` | 🔴 实测**私网数据处理量 0.049 > 公网 0.037 元/GB·小时**，客户按此直觉做网络设计会算反 |
| AG04 | `99.95% 的 SLA 承诺` / `SLA 承诺 99.95%` | 🔴 SLA 协议只承诺 serverless ≥99.90%，**[99.90%, 99.95%) 是无赔偿区**；拿产品页 99.95% 主张赔偿必然落空 |
| AG07 | `MCP 场景支持 JWT` | 官方专页明写 MCP 消费者认证「**仅支持 API Key**」（裁决 C9） |
| AG10 | `支持 A2A 协议转换` / `A2A 协议转换已支持` | llms.txt 产品描述提到 A2A，但 **189 页核心文档零命中**，不得对客承诺 |
| AG14 | `Vertex AI 配方要求跨境专线` | 🔴 该页**不含**跨境网络要求（只有「VPC 须绑公网 NAT」）。这条正是**主控在提示词里的错误断言**，被 W7 抵制；写成 forbidden 是防止它从别的路径混回知识库 |

**选取标准**：每条禁写串都是「**一旦出现在知识库里，就会直接导致对客答复错误**」的断言，
而不是格式或风格约束。写入前逐条 `grep` 实测在语料中命中 **0**（否则门禁会恒红）。

## 5. 沉淀到工艺层的两条结论

1. **指针卡越密集，回归用例越容易假绿。** 主控在 `aliyun-products.md` 写的指针卡本意是「不进正文、只给结论」，
   但结论写全了就等于把专题页的关键事实**复制了一份到语料里的另一个文件** → keyword 用例失去区分度。
   **今后新增专题页的回归用例，必须含至少 3 条「在专题页命中 > 0 且在指针卡命中 = 0」的锚定关键词**，
   并把「剔除专题页后该用例必须 FAIL」作为用例验收条件。
2. **新加的门禁能力必须先自证会 FAIL。** `forbidden` 这类否证机制如果只用「当前 0 违反」来验收，
   无法区分「知识库干净」与「检查没生效」。做法 = **注入一条必然命中的禁写串**，确认 FAIL 且能报出具体串，再还原。
