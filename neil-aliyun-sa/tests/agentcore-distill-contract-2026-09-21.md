## 2. 铁律（违反即返工）

### 2.1 🔴 事实来源只有两个：digest 与 raw。**你的背景知识一律不算证据**

- 找不到 → 写「**缺口**：官方文档未提及（已查 `<列出你查过的 slug>`）」
- **严禁**用你对阿里云 / AWS Bedrock AgentCore / 其他 Agent 平台的既有印象补全。后续会有**独立模型族（Kimi-K3）对照 raw/ 逐条核查**，任何补全都会被判幻觉并污染知识库
- 尤其严禁：编造单价、编造配额、编造地域清单、编造规格档位、编造 API 名、编造竞品对比

### 2.2 来源标注（AGENTS.md 硬要求）

每个事实句末尾标 `[官方]` / `[实战]` / `[推断]`：
- `[官方]` = digest/raw 里逐字可查。**这是绝大多数条目应有的标注**
- `[推断]` = 由两条以上官方原文组合推理得出。**必须同时写出推理所依据的原文**，例：`[推断] 依据：①「限免不包括 Agent 运行时的算力、存储和网关」②协议「不适用于免费的功能及版本」`
- `[实战]` = 本次蒸馏**没有**实战数据，除 RULINGS 里明确标了实战的条目外，**不要使用这个标注**
- `[官方矛盾]` = 官方文档自相矛盾（见 RULINGS B7/G6/G7），照实并列两个原句，**不替官方调和、不猜哪个对**
- 关键数字另附 URL + 抓取日期 `2026-09-20`

### 2.3 🔴 限定词一个都不许丢

「公测期间」「仅限白名单」「以下地域」「企业版」「不超过」「可提工单调整」「除非另有约定」「仅针对」这类限定词丢失，会让真事实变成谎言。这是本 KB 最危险的污染形式（有过对客翻车先例）。

**特别警示**：SLA 的「仅针对 AgentCore 平台自身的 Agent 运行时服务」和「本协议不适用于公测、邀测、免费的功能及版本」两条限定词，**丢了就是重大对客事故**。

### 2.4 表格不许压成散文

计费表、赔偿档位表、地域价表、配额表、依赖产品表、术语映射表一律 markdown 表格原样搬运。表格是 SA 报价与选型的直接依据，压成散文等于毁掉。

### 2.5 时效锚

凡带日期的信息（限免窗口、SLA 生效日、公测状态）必须写**绝对日期**并标注时效性，例：
`🔴 时效：2026-09-18 ~ 2026-10-18（GMT+8），蒸馏时点 2026-09-20 距活动结束 28 天；「活动结束后计费策略另行通知」→ 本节 2026-10-18 后必须复核`
