## 1. 这个知识库是给谁用的（决定你强调什么）

读者是**阿里云解决方案架构师（SA）**，用途是**对客答疑、方案设计、产品选型、报价量级、避坑**。
因此蒸馏时优先级从高到低：

| 优先级 | 内容类型 | 为什么 |
|---|---|---|
| 🔴 P0 | **数字**：价格、配额、上限、SLA 百分比、超时、粒度、地域清单、版本生效日期 | 对客报错数字＝事故 |
| 🔴 P0 | **边界与限制**：不支持什么、什么情况失效、哪些是设计行为而非 bug | 客户踩坑都在这 |
| 🟠 P1 | **选型判据**：A 形态 vs B 形态怎么选、什么场景用哪个能力 | SA 的主要产出 |
| 🟠 P1 | **依赖与连带计费**：用了 X 会不会另外开通/计费 Y | 「账单 ≠ 全成本」是对客高频争点 |
| 🟡 P2 | 操作步骤 | 只保留**有决策含义**的步骤（如「必须先建实例才能开通 X」），逐步点击流不抄 |
| ⚪ P3 | 控制台截图描述、界面文案、营销叙述 | 丢弃 |

**丢弃**：冗余背景、界面按钮位置描述、与选型/报价/避坑无关的运维细节。
**保留**：能力边界、quota、参数默认值与取值范围、计费项与单价、版本演进信号、官方原文里的限定词
（「仅」「不支持」「默认」「预计」「以…为准」这类词是事实的一部分，不要抹平）。

## 2. 事实标注（每条事实都要，无例外）

| 标签 | 含义 | 用法 |
|---|---|---|
| `[官方]` | raw 快照里有明文依据 | 句末标 `[官方｜<slug>]`，多个来源用 `｜` 分隔多个 slug |
| `[官方原文]` | 逐字引用（用 `>` 块引或引号） | 关键限定词、易被转述失真的条款、客户会逐字核对的口径 |
| `[官方矛盾]` | 两页/同页两处口径冲突 | **必须把冲突双方原文都摘出来**，不许自行裁决哪个对，交主控裁 |
| `[推断]` | 你从官方事实推出的结论 | 写清推理链（「由 A + B 推出 C」），不许把推断写成事实 |
| `[文档未说明]` | raw 里查无此项 | **主动标注**。SA 最需要的就是知道哪里是空白，别用常识填 |

slug 写法：用 raw 文件名去掉 `.md`（例 `[官方｜capacity-description]`）。
不要写完整 URL —— 主控在 §0 溯源节统一维护 slug↔URL 对照表。

## 3. 🔴 数字纪律（本项目已有血的教训）

1. **逐字照抄**，不许四舍五入、不许换算单位、不许合并区间。
   原文「0.037 元/GB/小时」就写 `0.037 元/GB/小时`，不要写成「约 0.04 元」。
2. 需要换算时**两个都写**：`0.037 元/GB/小时（原文）≈ 26.6 元/TB/月（[推断] 按 720 小时换算）`。
3. **表格里的数字连表头一起抄**，不要把多列表格压成一句话（丢维度＝丢事实）。
4. 数字有生效日期/地域/实例类型限定的，**限定词必须跟数字绑在一起写**。
   错：`可用性 99.99%` ｜ 对：`普通实例 ≥99.99%、Serverless 实例 ≥99.90%（2025-09-10 生效）`。
5. 同一数字在多页出现且不一致 → 打 `[官方矛盾]`，**不要挑一个写**。
6. 原文用「以官网价格页/控制台/账单为准」把数字推走的，照实记录这句话本身，
   并注明**这是文档级空白**（SA 报价时必须另走购买页核验）。

## 4. 输出格式

### 4.1 你负责的章节号与标题（不得自行增删章节号）

见下方 §6 分工表。每个章节以 `## §N 标题` 开头，内部自由分小节（`### N.x`）。

### 4.2 优先用表格

配额、价格、规格、地域、插件清单、能力对比、错误码 —— 一律表格。
表格列要含：项目 / 数值 / 限定条件（地域·实例类型·版本）/ 来源 slug。

### 4.3 每章末尾附「本章溯源」

```markdown
### §N 溯源
- `<slug>` — <官方标题>（<字节数>）：用于本章哪些结论
- ...
- **本章查无**：<列出你翻过但文档确实没写的高价值问题>
```

「本章查无」是**必填项**，不是可选项。写不出来说明你没在找边界。

### 4.4 篇幅

不设下限，设**信噪比要求**：宁可 300 行全是硬事实，不要 1500 行掺水。
不要复述原文段落，要**重排成 SA 可直接引用的结构**。

## 5. 报告格式（交付时随 partial 一起给主控）

```
W<n> 报告
- 读过的快照：<N> 个（逐个列 slug）
- 未使用的快照：<slug> + 原因（内容空/与他页重复/纯界面操作）
- 产出：/tmp/aigw-partials/W<n>-<主题>.md（<行数> 行，<表格数> 张表）
- 🔴 发现的官方矛盾：<逐条列出，含双方原文>
- 🔴 发现的文档级空白（SA 会被问到但文档没写）：<逐条>
- 🔴 与其他 worker 可能重叠的边界：<哪些 slug 你认为该归别人>
```

**如实报告优于漂亮报告。** 一份「看起来完整但漏了 3 页」的交付，比「明确说 3 页没用上」危害大得多。

## 8. 已知陷阱（前序工艺实测，省你时间）

- **`.md` 通道正文不含页面 H1 标题**。快照 frontmatter 里也没有标题字段。
  标题请从 `/tmp/aigw-shards/W<n>.tsv` 第 3 列取（那是 llms.txt 的官方链接文字）。
- 正文里的表格可能是 **HTML `<table>` 而非 Markdown 表格**（官方渲染残留），逐字保留其内容，
  重排成 Markdown 表格时**不许丢单元格**。
- 代码块语言标记可能是 `HELPCODEESCAPE-bash` / `-json` / `-plaintext` 这类渲染残留，
  引用时改回正常语言标记即可（这是格式修复，不算改事实）。
- 官方原文可能有错字，**逐字引用时保留错字**，可在后面加 `[原文如此]`。
- 有些页是**同一内容的两个 slug**（实测 `gateway-managed-mcp-services` 与 `mcp-gateway-management`
  正文 SHA256 完全相同）。发现重复请报告，只写一份内容并注明两个 slug。
- **公测/旧版内容有时效性**：涉及「公测」「旧版」「限时免费」的口径，必须把**时间边界**一起写出来
  （何时结束、之后如何），不要写成现在时。
