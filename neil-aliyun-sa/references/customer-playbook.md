# 客户话术 — customer-playbook.md

> **来源**：参考 `ad-industry-cloud-insights` 的客户底盘 × 客户类型矩阵。
> **定位**：与不同类型客户对话时的标准话术起点；不是死板照搬，而是定位锚点。

## 客户底盘分类（A / B / C 三类）

| 底盘 | 定位 | 典型 |
| --- | --- | --- |
| **A 入口型** | 自身就是流量 / 平台入口 | 互联网平台、超级 App、媒体 |
| **B 工具型** | 给入口型供工具 / 服务 | SaaS 厂、AdTech、数据服务、ToB 平台 |
| **C 代理 / 集成型** | 帮客户用云、代采、代运营 | 集成商、ISV、运营服务商 |

不同底盘的关键诉求和卖点不同：

### A 入口型客户的关注点

- 体量 + 弹性：能不能扛住峰值
- 数据闭环：用户行为 → 模型 → 业务回流
- 数据出海合规
- 与同行竞合
- AI 能力是否能直接接入业务（百炼、推荐、内容理解）

**话术起点**：从业务峰值 + 用户体验 + 数据资产开始切入，少谈基础设施细节，多谈业务结果。

### B 工具型客户的关注点

- 多租户架构、隔离能力
- 客户数据安全 / 数据清洁室
- 计费精细度（按客户拆分）
- 接入多云的能力
- 与上游平台的对接成本

**话术起点**：从客户的客户角度入手，谈如何让 ToB 客户更放心、更省事。

### C 代理 / 集成型客户的关注点

- 折扣 / 返点 / 商务空间
- 项目交付能力（实施、培训、运维）
- 工具链（多云管理、计费拆分、客户报表）
- 售后响应速度

**话术起点**：把云厂当成"上游供货"来谈，重点放在合作机制、商务模式、交付支持。

## 决策时延层级（L1-L5）

> **核心思想**：不同业务对决策延时容忍度差异极大，方案设计要先把客户业务的 L 级搞清楚。

| 层级 | 时延要求 | 典型场景 | 技术含义 |
| --- | --- | --- | --- |
| **L1 实时** | ≤ 100ms | 在线交易、实时风控、RTB 竞价 | 内存级、单机 / 同 AZ 闭环 |
| **L2 准实时** | 100ms - 1s | 推荐、广告点击预测、搜索 | 缓存 + 轻量服务 |
| **L3 分钟级** | 秒 - 分钟 | 实时报表、实时归因、对账 | 流计算 + 准实时存储 |
| **L4 小时级** | 小时 | T+1 报表、运营分析 | 离线 + Lambda 架构 |
| **L5 战略级** | 天 - 周 | 战略决策、模型重训、大盘复盘 | 离线大数据 + 数仓 + BI |

**用法**：
- 设计方案时，先标记业务每条链路的 L 级
- L1-L2 → 关注内存、网络延时、就近部署
- L3 → 关注流计算选型、消息中间件
- L4-L5 → 关注存储成本、数据治理、批处理

## 标准开场（按底盘）

### 给 A 类客户

> "您的业务峰值现在到了什么量级？日活 / 峰值 QPS 大概多少？哪些链路是 L1 实时（毫秒级）？数据闭环上有没有 AI 加持的空间？"

### 给 B 类客户

> "您面向的客户数大概在什么量级？多租户隔离做到什么粒度？数据合规上有没有清洁室 / 跨域同步的诉求？"

### 给 C 类客户

> "您现在主要服务哪类终端客户？项目交付的瓶颈在云能力还是工具链？商务模式上更看重折扣 / 返点 / 还是项目分润？"

## 反对声音处理（Top 5）

| 反对声 | 应对要点 |
| --- | --- |
| "AWS / 腾讯云更便宜" | 拉同等 SLA + 同等架构下的 TCO，不是单价；列出阿里云独有能力 |
| "我们正在多云策略" | 帮客户规划多云治理（Terraform / 跨云 K8s / 数据同步），不抢独占 |
| "切云风险大" | 提供分阶段、试点、并行、回退预案；让客户掌控节奏 |
| "上云后失控" | 强调治理体系（Landing Zone / Config / FinOps），让客户感觉"上云=升管控" |
| "国产替代 / 信创" | 走专有云 / 信创路径；强调全栈国产能力 |
