# IDC→云通用迁移方法论 — migration-methodology.md

> **定位**：通用的 IDC/自建→阿里云迁移方法论框架。各 S 场景（S1-S9）可引用此框架做迁移规划。
> **适用**：任何从自建 IDC、其他云、混合环境迁移到阿里云的场景。

## 迁移四阶段框架

```
┌──────────────┐   ┌──────────────┐   ┌──────────────┐   ┌──────────────┐
```

### Phase 1：评估（Assess）2-4 周

**目标**：摸清家底、量化迁移难度、确认业务价值。

#### 1.1 资产发现（Discovery）

| 发现维度 | 工具/方法 | 输出物 |
| --- | --- | --- |
| 服务器清单 | CMDBuild / CMDB 导出 / SMC Agent 扫描 | 主机台账（OS/CPU/Mem/Disk/IP） |
| 应用清单 | 架构访谈 + 端口扫描 + APM 数据 | 应用拓扑图（App → DB → MQ → Cache） |
| 数据资产 | DBA 提供 + DTS 预检 | 数据库实例清单（引擎/版本/容量/QPS） |
| 网络拓扑 | 现有网络文档 + 抓包分析 | 子网/VLAN/防火墙策略/互联链路图 |
| 依赖映射 | ARMS Agent / SLS 日志分析 / 流量镜像 | 调用链矩阵（谁调谁、频率、延迟） |

#### 1.2 TCO 分析

```
当前 IDC 年成本（全口径）：
  = 硬件折旧 + 机房租金 + 带宽 + 人力运维 + 灾备 + 冗余备件 + 电力制冷

目标云年成本：
  = 计算(ECS/ACK) + 存储(OSS/NAS/块) + 数据库(RDS/PolarDB) + 网络(带宽+GA+CEN) + 安全 + 运维工具

ROI 公式：
  = (IDC 年成本 - 云年成本 - 一次性迁移成本) / IDC 年成本 × 100%
  通常 ROI 目标 > 30% 才值得迁移
```

#### 1.3 风险与合规预评估

- **业务中断风险**：识别单点应用、长事务系统、对延迟敏感的调用链
- **数据合规**：等保要求、数据出境限制、行业监管（金融/医疗/教育）
- **技术债务**：老旧 OS（CentOS 6/Windows 2008）、EOL 数据库版本、自研中间件
- **团队能力**：云技能 Gap 评估，是否需要培训或引入 MSP 合作伙伴

#### 1.4 可迁移性评估矩阵

| 维度 | 低复杂度（1-2分） | 中复杂度（3-4分） | 高复杂度（5分） |
| --- | --- | --- | --- |
| 架构 | 无状态 Web 应用 | 主从 DB + 缓存 | 分布式事务 / 自研中间件 |
| 数据量 | < 500GB | 500GB-10TB | > 10TB |
| 可用性要求 | 可接受小时级停机 | 分钟级停机 | 零停机（金融/电商） |
| 依赖外部 | 无外部依赖 | 1-2 个外部 API | 多系统耦合 |
| 合规 | 无特殊要求 | 等保二级 | 等保三级 / 金融级 |

### Phase 2：规划（Plan）2-4 周

**目标**：确定目标架构、排定迁移波次、设计割接与回滚方案。

#### 2.1 Landing Zone 设计

参考 `caf-landing-zone.md`，核心决策点：

| 决策 | 推荐方案 | 说明 |
| --- | --- | --- |
| 账号结构 | Resource Directory 多账号 | 生产/测试/安全/日志分离 |
| 网络架构 | Hub-Spoke VPC + CEN | 统一出口、安全策略集中管控 |
| 身份认证 | RAM + SSO + IDP 对接 | 对接企业 AD/LDAP |
| 安全基线 | Cloud Firewall + WAF + SLS审计 | 开通即安全 |
| 成本管控 | 标签体系 + 预算告警 + RI/SP | 从 Day 1 开始成本可见 |

#### 2.2 迁移波次规划（Wave Planning）

**分波原则**：低风险先行，验证流程；核心系统最后。

```
Wave 0（试点）：开发/测试环境 → 验证网络通道 + 运维流程
Wave 1（低风险）：静态网站、报表系统、内部OA → 积累信心
Wave 2（中风险）：业务中台、微服务应用 → 验证复杂场景
Wave 3（高风险）：核心交易、数据库主库、有状态应用 → 精密割接
Wave 4（收尾）：遗留系统处理（退役/保留/重构）
```

**每 Wave 通用里程碑**：
1. Wave 详设评审通过
2. 目标环境就绪（网络/安全/计算/存储）
3. 数据全量同步完成 + 增量追平
4. 功能/性能验证通过
5. 割接窗口确认 + 回滚演练通过
6. 正式割接 + 业务验证
7. 老环境观察期（7-14 天）→ 退役

#### 2.3 割接策略选型

| 策略 | 适用场景 | 停机时间 | 复杂度 |
| --- | --- | --- | --- |
| 一次性割接（Big Bang） | 小型系统 / 可接受停机 | 小时级 | 低 |
| 灰度切流（Canary） | 无状态 Web / API | 零停机 | 中 |
| 读写分离切割 | 数据库场景 | 分钟级 | 中高 |
| 双写双读 | 金融/交易核心 | 零停机 | 高 |
| DNS 权重切换 | 全局流量 | 秒级 | 低 |

#### 2.4 回滚方案（必须预设）

- **网络层回滚**：DNS TTL 提前缩短至 60s；保留 VPN/专线双通道
- **数据层回滚**：DTS 反向同步链路预建好；快照/备份时间点 RPO 确认
- **应用层回滚**：灰度发布平台支持一键回退；配置中心保留双份
- **回滚触发条件**：提前定义阈值（错误率 > X%、延迟 > Yms、丢单 > Z 笔）
- **回滚演练**：正式割接前至少完整演练 1 次

### Phase 3：执行（Migrate）4-12 周

**目标**：按波次稳步执行，每 Wave 闭环验证。

#### 3.1 试点迁移（Wave 0）

- 选择 1-2 个非关键应用做端到端验证
- 验证内容：SMC 迁移流程 / DTS 同步延迟 / 网络连通性 / 监控告警覆盖
- 输出：《试点总结报告》+ 流程优化建议

#### 3.2 批量迁移执行

**服务器迁移**：

```
源服务器 ──[SMC Agent]──▶ 阿里云镜像 ──▶ ECS 实例
                            │
                            ├─ 增量同步（块级差异复制）
                            └─ 最终割接（停写 → 最后同步 → 启动 → 验证）
```

**数据库迁移**：

```
源 DB ──[DTS 全量+增量同步]──▶ RDS/PolarDB（只读追数据）
         │                               │
         ├─ Schema 迁移（DDL）             ├─ 数据校验（DTS 对比）
         ├─ 全量数据迁移                   ├─ 延迟监控（< 1s）
         └─ 增量日志回放（Binlog/Redo）    └─ 割接：源停写→确认追平→切VIP
```

**文件/对象存储迁移**：

```
NAS/本地存储 ──[ossutil/ossimport]──▶ OSS
大数据量(>10TB) ──[闪电立方/数据快递]──▶ OSS
在线迁移 ──[OSS Migration Tool]──▶ OSS（支持 S3/Azure Blob/七牛/又拍）
```

#### 3.3 割接执行 Checklist

```
割接前 T-24h：
  □ 回滚方案确认并邮件通知相关方
  □ DTS 同步延迟 < 1s 且持续稳定 24h
  □ 目标环境全栈监控正常
  □ DNS TTL 已缩短

割接中 T-0：
  □ 通知业务方进入割接窗口
  □ 源端停写（或切至只读）
  □ 等待 DTS 增量追平（确认 0 延迟）
  □ 目标端开放写入
  □ 切换 DNS / VIP / 负载均衡
  □ 业务验证（功能 + 性能 + 数据一致性）
  □ 确认割接成功 / 触发回滚

割接后 T+24h：
  □ 监控报警无异常
  □ 业务指标（订单量/响应时间/错误率）恢复正常
  □ 通知利益相关方割接完成
  □ 源端进入观察期（保留 7-14 天）
```

### Phase 4：优化（Optimize）持续

**目标**：从"能跑"到"跑得好/跑得省/跑得安全"。

#### 4.1 成本优化（上云后 1-3 月集中优化）

| 优化手段 | 预期节省 | 实施难度 |
| --- | --- | --- |
| RI/SP 预留实例 | 30-60% vs 按量 | 低（分析用量后购买） |
| 实例规格 Right-sizing | 10-30% | 中（需监控数据支撑） |
| Spot 实例（无状态/批处理） | 60-90% | 中（需容忍中断） |
| 存储分级（OSS IA/Archive） | 50-80% | 低（设置生命周期策略） |
| 弹性伸缩（HPA/VPA/CronHPA） | 20-40% | 中（需配置合理阈值） |
| 闲置资源清理 | 5-15% | 低 |

#### 4.2 性能调优

- **网络**：同 Region 跨 AZ 延迟 < 2ms 验证；开启 DCDN 动态加速
- **数据库**：慢查询分析 + 索引优化；PolarDB 读写分离负载验证
- **缓存**：Redis/Tair 命中率 > 95%；热 Key 检测与拆分
- **容器**：ACK 节点亲和性优化；Request/Limit 合理设置
- **CDN**：静态资源缓存命中率 > 90%；回源带宽优化

#### 4.3 安全加固

- Cloud Security Center 开通企业版（漏洞修复 + 入侵检测 + 基线核查）
- RAM 权限最小化 + 定期审计
- 日志审计全开（Actiontrail + SLS）
- 密钥管理（KMS）替换硬编码 AK/SK
- WAF 规则精细化 + Bot 防护

#### 4.4 运营卓越

- SLS + ARMS 全栈可观测体系搭建
- Terraform / ROS 基础设施即代码（IaC）
- 故障演练（PelicanDT / Chaos Engineering）
- 运维自动化（OOS 运维编排）
- 定期架构评审（Well-Architected Review 每季度 1 次）

## 迁移模式选型（6R）

| 模式 | 英文 | 说明 | 适用场景 | 工作量 | 云收益 |
| --- | --- | --- | --- | --- | --- |
| R1 | Rehost（搬迁） | 原样搬到云 VM | 时间紧 / 老系统 / 先迁后优化 | 低 | 低 |
| R2 | Replatform（换底座） | 小改，用云托管服务替换 | DB→RDS / 自建缓存→Tair | 中低 | 中 |
| R3 | Refactor（重构） | 重新设计架构，拥抱云原生 | 新业务 / 技术债重 / 需弹性 | 高 | 高 |
| R4 | Repurchase（换产品） | 换用 SaaS 替代 | 邮件→企业邮 / 自建 BI→Quick BI | 中 | 高 |
| R5 | Retain（保留） | 暂不迁移，保留在 IDC | 硬件绑定 / 合规限制 / EOL 不久 | 无 | 无 |
| R6 | Retire（退役） | 直接关停 | 无人使用 / 已被替代 | 低 | — |

**选型决策树**：

```
是否还有业务价值？
  ├── 否 → Retire（退役）
  └── 是 → 是否可以用 SaaS 替代？
           ├── 是 → Repurchase
           └── 否 → 有无合规/硬件限制不可迁？
                    ├── 是 → Retain（保留 + 混合云互联）
                    └── 否 → 是否需要现代化改造？
                             ├── 是 + 预算充足 → Refactor（云原生重构）
                             ├── 是 + 预算有限 → Replatform（托管化改造）
                             └── 否 / 时间紧 → Rehost（原样搬迁）
```

## 数据迁移工具链

| 工具 | 用途 | 支持场景 |
| --- | --- | --- |
| **DTS**（Data Transmission Service） | 数据库迁移/同步/订阅 | MySQL/PG/Oracle/SQL Server/MongoDB → RDS/PolarDB/OceanBase；全量+增量实时同步 |
| **SMC**（Server Migration Center） | 服务器整机迁移 | 物理机/VM/其他云 → ECS；块级增量复制；支持 Windows/Linux |
| **OSS Migration Tool** | 对象存储迁移 | S3/Azure Blob/GCS/七牛/又拍/NAS → OSS；并行传输+断点续传 |
| **HBR**（Hybrid Backup Recovery） | 备份与容灾 | ECS/NAS/OSS/本地文件 → 云备份仓库；支持 VMware vSphere 备份 |
| **闪电立方**（Data Transport） | 超大数据离线迁移 | > 10TB 场景；物理设备运输；加密传输 |
| **DBS**（Database Backup） | 数据库逻辑备份 | 长期归档、合规审计；异地备份 |
| **ADAM**（Advanced Database & Application Migration） | Oracle/DB2 迁移评估 | 兼容性分析 + SQL 改写 + 性能对比 |

**工具选型原则**：
- 数据库 < 1TB：DTS 在线全量+增量同步（推荐首选）
- 数据库 > 1TB：DTS + 预先 OSS 全量恢复（减少同步时间）
- 服务器整机：SMC（块级镜像 → ECS）
- 对象/文件 < 10TB：OSS Migration Tool 在线迁移
- 对象/文件 > 10TB：闪电立方 离线迁移 + ossutil 增量补齐
- Oracle/DB2 改造：ADAM 兼容性评估 → DTS 数据迁移 → 应用适配

## 网络迁移方案

### 典型四阶段网络演进

```
阶段 1：VPN 过渡（1-2 周搭建）
  IDC ──[IPsec VPN]──▶ VPC
  - 优点：快速开通，成本低（<1000元/月）
  - 缺点：延迟不稳定（公网波动），带宽有限（~200Mbps）
  - 用途：开发测试、管理通道、迁移初期数据同步通道

阶段 2：专线并行（2-4 周交付）
  IDC ──[Express Connect / 三方专线]──▶ VPC
  IDC ──[VPN backup]──────────────────▶ VPC
  - 推荐：1G 或 10G 物理端口 + 多 VBR 冗余
  - 延迟：同城 < 5ms，跨城 < 20ms
  - 用途：生产流量、大数据同步

阶段 3：专线切主（迁移中期）
  IDC ──[专线 Primary]──▶ VPC（生产流量）
  IDC ──[VPN Backup]────▶ VPC（备份通道）
  - 迁移流量走专线
  - VPN 作为故障切换通道

阶段 4：IDC 退出（迁移后期）
  VPC ──[CEN/TR]──▶ VPC（多 VPC 互联）
  保留 VPN/专线 作为混合云管理通道（可选）
  - 全量业务在云上
  - 保留最小化回联通道（观察期）
```

### 网络关键设计决策

| 决策 | 推荐 |
| --- | --- |
| VPC CIDR 规划 | 与 IDC 不冲突；预留扩展空间；按环境/业务分 VPC |
| DNS 解析 | PrivateZone + 混合云 DNS 联动；避免硬编码 IP |
| 安全策略 | Cloud Firewall 统一策略管控；零信任分段 |
| 流量出口 | NAT Gateway 统一出口 + 共享带宽包 |
| 多 Region 互联 | CEN Transit Router（带宽按需购买） |

## 风险控制清单

| 风险类别 | 风险描述 | 影响 | 缓解措施 |
| --- | --- | --- | --- |
| **数据丢失** | 迁移过程中数据不一致或丢失 | 致命 | DTS 数据校验；全量+增量双保险；割接前完整备份 |
| **业务中断** | 割接窗口超时或割接失败 | 严重 | 回滚方案预建好；割接演练至少 1 次；灰度切流 |
| **性能劣化** | 迁移后延迟增加或吞吐下降 | 严重 | 迁移前 Benchmark 基线；目标规格 >= 源端；性能测试验收 |
| **安全漏洞** | 迁移期间暴露面增大 | 严重 | 迁移通道加密（TLS/VPN）；最小权限；安全组精细控制 |
| **成本超预算** | 双跑期间双倍成本 | 中 | 控制双跑时间（< 30 天）；分波迁移逐步释放 IDC |
| **团队技能不足** | 操作失误导致事故 | 中 | 培训 + Runbook + MSP 协助；关键操作双人校验 |
| **依赖系统阻塞** | 外部系统未配合改造 | 中 | 提前识别依赖方；通过 API Gateway/NAT 做过渡 |
| **合规阻断** | 数据驻留/等保要求不满足 | 严重 | 提前确认 Region 合规；等保测评提前介入 |

## 迁移验证检查表

### 功能验证

- [ ] 核心业务流程端到端测试通过（参考 UAT 用例）
- [ ] API 接口返回值与源端一致（对比测试）
- [ ] 定时任务/批处理正确执行
- [ ] 消息队列消费无积压、无丢失
- [ ] 文件上传下载正常（OSS 路径验证）
- [ ] 第三方系统对接正常（支付/短信/物流等）

### 性能验证

- [ ] 响应时间 P95 <= 源端基线 * 1.1（允许 10% 波动）
- [ ] 吞吐量达到预期峰值（压测验证）
- [ ] 数据库 QPS/TPS 恢复到源端水平
- [ ] 缓存命中率 > 源端水平
- [ ] 弹性伸缩策略验证（扩容/缩容触发正确）

### 数据验证

- [ ] 数据行数一致性校验通过（源 vs 目标）
- [ ] 关键字段抽样校验通过（金额/状态/时间戳）
- [ ] 增量同步延迟 < 1s 并持续稳定
- [ ] 数据完整性校验（MD5/CRC 对比）

### 安全验证

- [ ] 安全组/ACL 策略生效（非授权端口不可访问）
- [ ] WAF 防护规则生效（SQL注入/XSS 测试）
- [ ] SSL 证书正确配置（HTTPS 无告警）
- [ ] RAM 权限最小化验证
- [ ] 日志审计全量采集确认

### 运维验证

- [ ] 监控告警覆盖全部关键指标
- [ ] 日志采集链路正常（应用日志 → SLS）
- [ ] 备份策略执行正常（自动快照/DBS 备份）
- [ ] 运维 Runbook 更新完成
- [ ] 值班通知链路验证
