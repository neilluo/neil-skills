# Lint — 知识库健康检查 SOP（6维 + P0/P1/P2 分级）

## 触发条件

- 用户显式要求："lint" / "检查" / "健康检查"
- 每 5 次 ingest 操作后，系统建议执行
- 知识库长时间未维护（> 30 天）

---

## 6 维检查详细

### 维度 1: 矛盾检测 → P0（最高优先级）

**检查内容**：同一事实在不同页面中表述不一致

**检测方法**：
1. 扫描所有 wiki 页面，提取"事实性断言"（数值、默认值、行为描述）
2. 按主题聚类，对比同一主题下的不同表述
3. 标记不一致之处

**示例**：
```
❌ P0 矛盾检测
- wiki/entities/redis.md: "默认超时 30s"
- wiki/guides/caching-best-practice.md: "Redis 默认超时 60s"
- 修复建议：核查官方文档确认正确值，统一修改
```

**P0 理由**：矛盾的信息比没有信息更有害，会导致错误决策。

### 维度 2: 过时检测 → P1

**检查内容**：标注日期超过 6 个月未验证的页面

**检测方法**：
1. 读取每个页面的 frontmatter `updated` 字段
2. 计算距今时间差
3. 超过 6 个月的标记为 `[stale-YYYY]`

**输出**：
```
⚠️ P1 过时检测
- wiki/entities/webpack-config.md — 最后更新: 2024-01-15 (>6月)
  → 建议：标记 [stale-2024]，安排验证
- wiki/concepts/microservice-pattern.md — 最后更新: 2023-11-20 (>6月)
  → 建议：核查是否有新版本/新实践
```

**处理方式**：
- 在页面顶部添加 `> ⚠️ [stale-YYYY] 本页内容可能过时，请验证后移除此标记`
- 不删除内容，仅标记

### 维度 3: 孤立页检测 → P2

**检查内容**：没有任何入站 `[[引用]]` 的页面

**检测方法**：
1. 扫描所有页面，建立被引用关系图
2. 找出入站引用数为 0 的页面（index.md 中的引用不计入）
3. 排除 index.md / inbox.md / log.md 等系统页面

**输出**：
```
📋 P2 孤立页检测
- wiki/concepts/orphan-concept.md — 无任何页面引用
  → 建议：在相关页面添加 [[orphan-concept]] 引用，或评估是否需要保留
```

**P2 理由**：孤立页不影响正确性，但影响可发现性。

### 维度 4: 缺页检测 → P1

**检查内容**：被 `[[link]]` 引用但对应文件不存在的概念

**检测方法**：
1. 扫描所有页面中的 `[[page-name]]` 引用
2. 检查对应文件是否存在于 wiki 目录中
3. 列出所有"悬空引用"

**输出**：
```
⚠️ P1 缺页检测
- [[api-gateway]] 被引用于 3 个页面，但文件不存在
  → 引用位置：entities/microservice.md, guides/deployment.md, concepts/load-balancing.md
  → 建议：创建 wiki/entities/api-gateway.md 或修正引用
```

### 维度 5: [[wikilink]] 完整性 → P1

**检查内容**：所有 `[[link]]` 必须指向存在的页面

**检测方法**：
1. 提取所有 `[[page-name]]` 格式的链接
2. 验证每个链接指向的文件存在
3. 检查链接格式是否规范（无路径前缀、无 .md 后缀）

**输出**：
```
⚠️ P1 Wikilink 完整性
- wiki/guides/setup.md 第 15 行: [[install-guide.md]] — 格式错误，应为 [[install-guide]]
- wiki/entities/docker.md 第 8 行: [[kubernetes]] — 目标文件不存在
```

**与维度 4 的区别**：维度 4 关注"缺了什么内容"，维度 5 关注"链接格式是否正确"。

### 维度 6: 数据空白 → P2

**检查内容**：知识覆盖不足的领域

**检测方法**：
1. 分析现有页面的主题分布
2. 识别与项目相关但未覆盖的领域
3. 参考 raw/ 中已归档但未充分蒸馏的源文件

**输出**：
```
📋 P2 数据空白
- 领域 "错误处理" — 仅有 1 篇相关页面，raw/ 中有 3 篇未处理的相关源
  → 建议：对 raw/20240110-error-handling.md 执行 ingest
- 领域 "性能优化" — 无覆盖
  → 建议：搜索补充相关知识
```

## 自动修复建议

### 可自动修复（无需人工确认）

| 问题类型 | 自动修复方式 |
|---------|------------|
| Wikilink 格式错误（含 `.md` 后缀） | 自动移除 `.md` 后缀 |
| 孤立页（P2） | 在 index.md 对应分区补充引用 |
| 过时标记 | 自动添加 `[stale-YYYY]` 标记 |

### 需人工确认（不可自动修复）

| 问题类型 | 原因 |
|---------|------|
| 矛盾（P0） | 需要判断哪个版本正确 |
| 缺页（P1） | 需要决定是创建页面还是删除引用 |
| 数据空白（P2） | 需要决定是否值得投入时间补充 |

## 与回归测试的关系

| 维度 | Lint | Regression |
|------|------|-----------|
| 关注点 | 语义质量（正确性/一致性/完整性） | 覆盖率（知识面是否回退） |
| 检测对象 | 现有内容的健康状态 | 更新后是否丢失已有知识 |
| 触发时机 | 定期 / 手动 | 每次大规模更新后 |
| 互补关系 | Lint 确保"有的东西是对的" | Regression 确保"对的东西还在" |

两者互补：
- Lint 后发现大量 P0/P1 问题 → 可能需要 Regression 确认修复没有引入新问题
- Regression 发现覆盖率下降 → 应立即执行 Lint 定位具体问题
