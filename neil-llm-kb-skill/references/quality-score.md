# KB Health Score — 知识库质量评分体系

## 概述

KB Health Score 是一个量化指标体系，用于评估知识库的**完整性、一致性、可发现性和维护状态**。
总分 100 分，由 5 个维度加权组成。

---

## 评分模型

```
KB Health Score = Σ (维度分 × 权重)

总分 = 结构完整性(25%) + 内容质量(30%) + 连通性(20%) + 新鲜度(15%) + 覆盖率(10%)
```

| 等级 | 分数范围 | 含义 |
|------|---------|------|
| A+ | 95-100 | 生产就绪，可作为 Agent 主要知识源 |
| A | 85-94 | 优秀，少量边缘问题 |
| B | 70-84 | 良好，有明确改进方向 |
| C | 50-69 | 及格，存在显著缺口 |
| D | < 50 | 需要大规模重建 |

---

## 维度 1: 结构完整性（25 分）

### 检查项

| 检查项 | 满分 | 扣分规则 |
|--------|------|---------|
| index.md 存在且包含所有页面 | 5 | 每个遗漏页面 -0.5，最多扣 5 分 |
| inbox.md 状态机正常（无 stuck pending） | 3 | 每个 stuck > 7 天的 pending -1 |
| log.md 连续且无 gap | 3 | 每个时间 gap > 14 天 -1 |
| SCHEMA.md 存在且 ≤200 行 | 3 | 不存在 -3；超 200 行 -1 |
| AGENTS.md 存在且格式合规 | 3 | 不存在 -3；格式错误 -1 |
| 目录结构完整（entities/concepts/guides/comparisons） | 3 | 每缺一个 -1 |
| frontmatter 规范率（所有页面含完整 frontmatter） | 5 | 合格率每低 10% 扣 1 分 |

### 计算公式

```
结构分 = 25 - 总扣分（不低于 0）
```

---

## 维度 2: 内容质量（30 分）

### 检查项

| 检查项 | 满分 | 扣分规则 |
|--------|------|---------|
| 证据标注率（每页标注 [primary]/[derived]/[inferred]） | 8 | 未标注页面占比每 10% 扣 1 分 |
| [primary] 占比 ≥ 50% | 5 | 每低 10% 扣 1 分 |
| [inferred] 占比 ≤ 30% | 5 | 每超 10% 扣 2 分 |
| 页面四段落完整度（概述/详细/交叉引用/来源） | 7 | 缺段落页面占比每 10% 扣 1 分 |
| 无矛盾（P0 lint 为 0） | 5 | 每个 P0 矛盾 -2，最多扣 5 分 |

### 计算公式

```
内容分 = 30 - 总扣分（不低于 0）
```

---

## 维度 3: 连通性（20 分）

### 检查项

| 检查项 | 满分 | 扣分规则 |
|--------|------|---------|
| 平均出站 [[wikilink]] ≥ 3 | 6 | 平均值每低 0.5 扣 1 分 |
| 孤立页占比 ≤ 5% | 5 | 每超 5% 扣 2 分 |
| 断链数 = 0 | 4 | 每个断链 -1，最多扣 4 分 |
| 缺页数 ≤ 3 | 3 | 每个缺页 -1，最多扣 3 分 |
| 双向引用率 ≥ 60%（A 引用 B，B 也引用 A） | 2 | 低于 60% -1，低于 40% -2 |

### 计算公式

```
连通分 = 20 - 总扣分（不低于 0）
```

---

## 维度 4: 新鲜度（15 分）

### 检查项

| 检查项 | 满分 | 扣分规则 |
|--------|------|---------|
| 过时页面（> 6 月未更新）占比 ≤ 10% | 6 | 每超 10% 扣 2 分 |
| 最近 30 天有 ingest/update 活动 | 4 | 无活动 -4 |
| 无 [stale] 标记的页面 | 3 | 每个 stale 页面 -1 |
| log.md 最近条目 ≤ 7 天 | 2 | 8-30 天 -1，>30 天 -2 |

### 计算公式

```
新鲜度分 = 15 - 总扣分（不低于 0）
```

---

## 维度 5: 覆盖率（10 分）

### 检查项

| 检查项 | 满分 | 扣分规则 |
|--------|------|---------|
| raw/ 文件已全部处理（inbox Done 率 100%） | 4 | 每个未处理 -1 |
| wiki 页面数 / raw 文件数 比值 ≥ 2.0 | 3 | 比值每低 0.5 扣 1 分 |
| 回归测试通过率 ≥ 85% | 3 | 每低 5% 扣 1 分 |

### 计算公式

```
覆盖率分 = 10 - 总扣分（不低于 0）
```

## 执行方式

### 手动评分（lint 扩展）

在 lint 操作末尾追加评分摘要：

```markdown
## 📊 KB Health Score

| 维度 | 得分 | 满分 | 说明 |
|------|------|------|------|
| 结构完整性 | 23 | 25 | inbox 有 1 个 stuck pending |
| 内容质量 | 27 | 30 | 3 个页面缺少证据标注 |
| 连通性 | 18 | 20 | 2 个孤立页 |
| 新鲜度 | 14 | 15 | 1 个 stale 标记 |
| 覆盖率 | 9 | 10 | 回归测试 90% |

**总分：91/100 — 等级 A**

### 改进建议（按 ROI 排序）
1. 处理 stuck pending（+1 结构分）
2. 补充 3 个页面的证据标注（+2 内容分）
3. 为孤立页添加引用（+2 连通分）
```

### 自动评分脚本（未来集成）

评分逻辑可集成到 `regression-template.py` 中作为附加模块：

```python
def calculate_health_score(kb_dir: Path) -> dict:
    """Calculate KB Health Score across 5 dimensions"""
    scores = {
        "structure": assess_structure(kb_dir),      # /25
        "quality": assess_quality(kb_dir),          # /30
        "connectivity": assess_connectivity(kb_dir), # /20
        "freshness": assess_freshness(kb_dir),      # /15
        "coverage": assess_coverage(kb_dir),        # /10
    }
    scores["total"] = sum(scores.values())
    scores["grade"] = grade_from_score(scores["total"])
    return scores
```

## 与 Lint 的关系

| 维度 | Lint 产出 | Health Score 用途 |
|------|----------|-----------------|
| 矛盾检测 (P0) | 具体矛盾列表 | 作为内容质量扣分依据 |
| 过时检测 (P1) | stale 页面列表 | 作为新鲜度扣分依据 |
| 孤立页 (P2) | 孤立页列表 | 作为连通性扣分依据 |
| 缺页 (P1) | 缺页列表 | 作为连通性扣分依据 |
| 断链 (P1) | 断链列表 | 作为连通性扣分依据 |
| 数据空白 (P2) | 空白领域列表 | 作为覆盖率参考 |

**Lint 是细粒度问题定位，Health Score 是宏观质量量化。**
两者互补：Lint 告诉你"哪里有问题"，Health Score 告诉你"整体有多好"。

## 基准线参考

| 知识库阶段 | 预期 Health Score | 说明 |
|-----------|-----------------|------|
| 刚 init（空 KB） | 30-40 | 仅有结构分 + 部分新鲜度分 |
| 首轮 ingest 后 | 50-65 | 内容开始填充，连通性待建设 |
| 3 轮 ingest + 1 次 lint | 70-80 | 基本可用，进入 B 级 |
| 持续维护 2 周+ | 85-95 | 进入 A 级，Agent 可靠使用 |
| 成熟 KB（1 月+） | 95-100 | A+ 级，高质量知识源 |
