# neil-bootstrap-skill

Generate a pair of idempotent shell scripts (`start.sh`, `stop.sh`) at a project root by detecting the project's tech stack.

## When to use

Trigger when the user asks to:
- create / generate start.sh or stop.sh
- write bootstrap / launch scripts
- enable 一键启动 / 停止
- automate project startup with port-cleanup

## Hard rules

1. Scripts live at the **project root** (same directory as the stack marker file).
2. Logs go to **`./server_bootstrap.log`** — a single file, truncated on every `start.sh` run.
3. **Never use PID files.** Stop by port using `lsof -ti:PORT | xargs kill -9`.
4. **Readiness timeout is 180s per service.** Each service gets its own 180s window.
5. Scripts must be **idempotent**: re-running `start.sh` while the previous run is still active must cleanly kill the old process and relaunch.
6. `chmod +x` both files after writing.
7. After generation, **run `./start.sh` yourself** to verify it works, then `./stop.sh` to clean up.
8. **Always rebuild on every `start.sh` run when the start command consumes a pre-built artifact** (e.g. `java -jar target/*.jar`, a Go/Rust binary, a bundled `dist/`). Do **not** make the build conditional on "jar missing" — that causes stale-code bugs after source edits. Provide an opt-out env var (e.g. `SKIP_BUILD=1`) for the rare case where the user wants to skip rebuild. This rule does **not** apply to dev-mode commands that compile on demand themselves: `mvn spring-boot:run`, `./gradlew bootRun`, `npm run dev`, `go run .`, `cargo run`, `uvicorn ... --reload`.

## Execution flow

### Step 1 — Detect the tech stack

Scan the project root (and one-level subdirectories) for marker files, in this priority order:

| Marker file | Stack | Default start command | Port config |
|---|---|---|---|
| `pom.xml` | Maven + Spring Boot | `mvn spring-boot:run` | `src/main/resources/application.yml` or `.properties` → `server.port` (default 8080) |
| `build.gradle` / `build.gradle.kts` | Gradle + Spring Boot | `./gradlew bootRun` | same as above |
| `package.json` with `scripts.dev` | Node / Vite / Next | `npm run dev` | `vite.config.*` / `next.config.*` → `server.port` (default 3000) |
| `package.json` with `scripts.start` only | Node | `npm start` | `.env` / source (default 3000) |
| `requirements.txt` or `pyproject.toml` | Python | Choose by framework: `uvicorn main:app --reload`, `flask run`, `python manage.py runserver`, or `python main.py` | `.env` or source |
| `go.mod` | Go | `go run .` | source |
| `Cargo.toml` | Rust | `cargo run` | source |

### Step 2 — Detect frontend-backend split

If a backend marker is at the root AND a child directory matching `frontend/`, `web/`, `client/`, or `ui/` contains its own `package.json`, treat as a two-service project. Both services must be started by `start.sh`.

### Step 3 — Extract configured ports

- Read `application.yml` / `application.properties` for `server.port`.
- Read `vite.config.*` / `next.config.*` for `server.port`.
- Fall back to the "default port" column above only when config is missing.
- Record every port that will be used — `stop.sh` targets exactly these ports.

### Step 4 — Detect required env vars

- Scan `application.yml` / `.env` for placeholders like `${VAR_NAME:-default}` or `${VAR_NAME}`.
- **Distinguish required vs optional**: placeholders WITHOUT a default value (e.g. `${QODER_PAT}`) are **required** — script must abort if unset. Placeholders WITH a default (e.g. `${QODER_BASE_URL:https://...}`) are optional — warn only.
- If the project has a `.env` or `.env.example` file, `start.sh` must `source` the `.env` file before checking vars. If `.env` is missing, abort with a clear message pointing to `.env.example`.

### Step 5 — Write the scripts

Use the templates below, filling in the service definitions. **Do not** leave commented-out placeholders for unused stacks; generate exactly what this project needs.

### Step 6 — Make executable and verify

```bash
chmod +x start.sh stop.sh
./start.sh                           # run it
# read server_bootstrap.log and terminal output to confirm success
./stop.sh                            # verify clean shutdown
lsof -ti:<PORT>                      # should be empty
```

If verification fails, inspect `server_bootstrap.log`, fix the script, and repeat.

## start.sh template

```bash
#!/usr/bin/env bash
# Generated by neil-bootstrap-skill
set -u

cd "$(dirname "$0")"
LOG="./server_bootstrap.log"
: > "$LOG"   # truncate previous run's log

READY_TIMEOUT=180   # seconds per service

log() { echo "$@" | tee -a "$LOG"; }

free_port() {
  local port="$1"
  local pids
  pids=$(lsof -ti:"$port" 2>/dev/null || true)
  if [ -n "$pids" ]; then
    log "[port $port] occupied by pids: $pids, killing..."
    # shellcheck disable=SC2086
    kill -9 $pids 2>/dev/null || true
    sleep 1
  fi
}

require_env() {
  local name="$1"
  if [ -z "${!name:-}" ]; then
    log "✗ env $name is required but not set. Aborting."
    exit 1
  fi
}

warn_env() {
  local name="$1"
  if [ -z "${!name:-}" ]; then
    log "⚠  env $name is not set (continuing with default)"
  fi
}

# Probe both IPv4 and IPv6 because some dev servers (e.g. Vite) bind only ::1
probe_port() {
  local port="$1"
  nc -z 127.0.0.1 "$port" 2>/dev/null || nc -z ::1 "$port" 2>/dev/null
}

wait_ready() {
  local name="$1" port="$2" pid="$3"
  local i
  for i in $(seq 1 "$READY_TIMEOUT"); do
    if probe_port "$port"; then
      log "✓ $name ready  http://localhost:$port  (pid=$pid)  after ${i}s"
      return 0
    fi
    if ! kill -0 "$pid" 2>/dev/null; then
      log "✗ $name process exited before becoming ready (pid=$pid)"
      log "---- last 30 lines of $LOG ----"
      tail -n 30 "$LOG"
      return 1
    fi
    sleep 1
  done
  log "✗ $name did not become ready within ${READY_TIMEOUT}s"
  log "---- last 30 lines of $LOG ----"
  tail -n 30 "$LOG"
  return 1
}

start_service() {
  local name="$1" port="$2" workdir="$3"
  shift 3
  free_port "$port"
  log "[$name] starting in $workdir: $*"
  ( cd "$workdir" && nohup "$@" >> "$LOG" 2>&1 ) &
  local pid=$!
  wait_ready "$name" "$port" "$pid" || return 1
}

# ==========================================================
# AGENT: fill in the following based on detection:
# 1) source .env file (if project uses one)
# 2) require_env for required vars / warn_env for optional vars
# 3) any dependency prep (e.g. npm install)
# 4) one start_service call per detected service
#
# Example (frontend-backend split with .env):
#     if [ -f backend/.env ]; then
#       set -a; source backend/.env; set +a
#     else
#       log "✗ backend/.env not found. Copy from .env.example and fill in values."
#       exit 1
#     fi
#     require_env QODER_PAT
#     warn_env OPTIONAL_VAR
#     [ -d frontend/node_modules ] || (cd frontend && npm install)
#     start_service backend 8080 backend mvn spring-boot:run
#     start_service frontend 3000 frontend npm run dev
# ==========================================================

# <<< AGENT FILL HERE >>>

log ""
log "All services started. Logs: $LOG"
```

## stop.sh template

```bash
#!/usr/bin/env bash
# Generated by neil-bootstrap-skill
cd "$(dirname "$0")"

# AGENT: fill PORTS with every port that start.sh uses
PORTS=( <<< AGENT FILL PORTS HERE >>> )

for port in "${PORTS[@]}"; do
  pids=$(lsof -ti:"$port" 2>/dev/null || true)
  if [ -n "$pids" ]; then
    echo "[port $port] killing pids: $pids"
    # shellcheck disable=SC2086
    kill -9 $pids 2>/dev/null || true
  else
    echo "[port $port] already free"
  fi
done

exit 0
```

## Platform notes

- Works on macOS and Linux. Requires `bash`, `lsof`, `nc`, `nohup`, `kill`.
- On Linux distros that ship `ncat` instead of classic `nc`, substitute readiness probe with: `bash -c ':</dev/tcp/127.0.0.1/PORT'`.
- Some dev servers (e.g. Vite) bind IPv6 `::1` only. The `probe_port` helper in the template already tries both `127.0.0.1` and `::1`.
- Native Windows is not supported; recommend WSL or Git Bash.

## Anti-patterns — do not do these

- ❌ Writing PID files. Port-based stop is more robust.
- ❌ Rotating / archiving logs. Single-run log is the point.
- ❌ Hardcoding project names or paths. Scripts are generated per-project based on detection.
- ❌ Swallowing failures silently. Always `tail -n 30` the log on failure.
- ❌ Leaving unused stack branches in the generated script. Output only what applies.
- ❌ Skipping the build when a pre-built artifact already exists (e.g. `if [ ! -f target/x.jar ]; then mvn package; fi`). This silently runs stale code after source edits. Default to **always rebuild**; gate skipping behind an explicit `SKIP_BUILD=1`.

## Validation checklist

Before declaring done:

- [ ] `./start.sh` prints `✓ <service> ready` for every service
- [ ] Each service's configured port responds to a TCP probe
- [ ] `./stop.sh` frees every port (`lsof -ti:PORT` returns nothing)
- [ ] Re-running `./start.sh` while services are up succeeds (idempotency)
- [ ] `server_bootstrap.log` is truncated on each new `start.sh`
- [ ] `.gitignore` excludes `server_bootstrap.log` (add if missing)
