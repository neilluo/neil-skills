# Waker 完整配置指南

> 创建 Waker 后的全面配置——技能、连接器、项目、权限和记忆的最佳实践。

## 概述

创建 Waker 只是第一步，完整配置决定了数字员工的工作能力上限。本指南覆盖技能安装、连接器对接、项目绑定、权限设置和记忆管理五大维度。

## 详细内容

### 技能配置

| 来源 | 操作 |
|------|------|
| 技能市场 | 从 Qoder 官方 Skills Marketplace 搜索安装 |
| 上传自定义 | 本地导入自定义技能包 |
| 内置技能 | 系统自带，不可卸载 |

**最佳实践**：先安装角色相关的核心技能，再按需扩展。

### 连接器配置

进入 **员工详情 → 连接器** 手动添加：
- GitHub（代码仓库操作）
- Jira（项目管理）
- GitLab（CI/CD 集成）

**注意**：连接器是事件触发的前提——要监听 GitHub Issue 变化，必须先连接 GitHub。

### 项目绑定

进入 **员工详情 → 项目**：
- 绑定本地目录或 Git 仓库
- 一个项目支持多个源（多目录/多仓库）
- 项目有独立记忆，与员工个人记忆分离

**最佳实践**：每个 Waker 绑定其职责相关的项目，避免跨项目权限过大。

### 权限设置

进入 **员工详情 → 权限**，逐层配置：

1. **工具防护**：系统内置 6 类安全规则自动生效
2. **文件防护**：设置读写权限路径范围
3. **内置工具策略**：为每个工具设定允许/询问/禁用

**最佳实践**：初期使用"询问"策略，观察员工行为后逐步开放"允许"。

### 记忆管理

- **自动沉淀**默认开启，无需配置
- 定期进入记忆页检查，删除错误记忆
- 手动写入关键项目约定（如编码规范、部署流程）

### 自动修复 Bug 示例

**方法 A（手动对话）**：
1. 选后端工程师角色的 Waker
2. 输入："帮我排查这个报错的根因并给出最小修复方案"
3. 确认后让他执行修复并提 PR

**方法 B（自动任务）**：
1. 员工详情 → 触发任务 → 新建
2. 触发方式选"事件"，监听 GitHub Issue 变化
3. 任务描述："有新 Bug Issue 进来时，自动分析并给出修复 PR"
